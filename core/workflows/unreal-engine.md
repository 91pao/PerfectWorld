# Unreal Engine 工作流

## 调查范围

处理 UE 功能、Bug 或审查时，先确认与任务相关的：

- C++ 类、模块、注册入口和活跃调用者。
- Blueprint、Widget、DataAsset、DataTable、GameplayTag 与编辑器配置。
- 数据来源、状态所有者、生命周期、事件或 RPC 路径。
- 持久化、网络权威、确认和清理路径。

## 决策顺序

对每项职责选择一种路径：`reuse`、`configure`、`extend` 或 `create`。先寻找现有实现和配置；只有证据表明不能复用或配置时，才扩展或创建。

## 实施边界

- UI 的角标、数量、Brush 等表现差异默认不是独立业务状态。
- 多个界面展示同一状态时，复用同一个权威来源，避免镜像状态、重复存档或无依据同步。
- 新增 DataAsset、RPC、委托、管理器、缓存、状态代理或生命周期覆写时，重新检查职责与所有权。
- Blueprint 和 C++ 的绑定、暴露 API、资产路径与默认值属于同一变更面，应一起验证。

## 结束条件

完成前明确哪些路径已经在源码、配置、编辑器或运行环境中验证，哪些仍是风险或未覆盖项。不要将代码阅读、检索命中或资产元数据当作运行时行为证明。
