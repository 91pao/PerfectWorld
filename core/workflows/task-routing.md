# 任务路由

每轮根据用户最新目标重新选择一个主工作流。需要其他视角时，以补充检查的方式加入，不要无目的加载全部规则。

| 任务 | 主方向 |
| --- | --- |
| 想法、产品方向、范围取舍 | 产品与方案 |
| 需求、Issue、Ticket、验收标准 | 规格与计划 |
| 复杂功能、架构、跨团队方案 | 计划与架构评审 |
| 报错、异常、回归、根因 | 调查与修复 |
| 当前改动、PR、代码风险 | 代码审查 |
| 可维护性、复杂度、技术债 | 健康检查 |
| 认证、授权、数据安全、威胁模型 | 安全分析 |
| 网站或应用可用性 | QA |
| 只需要问题清单 | 只读 QA |
| UI、交互、视觉一致性 | 设计与体验 |
| 浏览器自动化、登录页、网页数据 | Web 工具 |
| API、CLI、SDK、文档上手 | 开发者体验 |
| 文档、发布说明、维护记录 | 文档维护 |
| 合并、发布、部署、上线后观察 | 发布流程 |
| 性能回归、成本或模型对比 | 基准与性能 |
| 项目长期记忆、上下文沉淀 | 项目记忆 |
| Unreal Engine、Blueprint、资产或编辑器 | UE 工程工作流 |

无论选择哪一项，都遵守 [Agent Contract](../AGENT-CONTRACT.md) 中的证据、授权和验证边界。
