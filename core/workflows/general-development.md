# 通用开发工作流

## 分流

| 任务特征 | 优先动作 |
| --- | --- |
| 想法、方向、范围不清 | 澄清目标、受众、约束和成功标准 |
| 需求、Issue、接口设计 | 形成可执行规格、依赖与验收条件 |
| 功能实现或重构 | 先定位入口、调用者、数据边界和既有模式 |
| 报错或异常 | 复现、缩小范围、提出可验证假设并追踪根因 |
| 审查或上线前检查 | 关注真实回归、兼容性、安全、测试缺口和发布风险 |

## 执行循环

1. 确认目标、禁止项和可修改范围。
2. 搜索相关代码和配置，读取最小必要上下文。
3. 选择复用、配置、局部扩展或新建实现。
4. 实施最小改动，并同步维护直接受影响的测试和文档。
5. 运行与改动风险匹配的检查，记录结果和剩余风险。

## 审查重点

- 边界条件、错误处理、并发与资源释放是否符合当前项目模式。
- 对外接口、数据结构和配置是否破坏现有调用者。
- 测试是否覆盖新行为和最可能回归的路径。
- 文档是否描述真实行为，而不是理想行为。
