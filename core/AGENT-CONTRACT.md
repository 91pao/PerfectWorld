# PerfectWorld Agent Contract

## 工作原则

- 以用户最新目标和当前工作区为准，先阅读现有实现、配置和调用关系，再提出方案或修改。
- 选择最小且兼容当前项目的改动。已有能力可复用或配置时，不平行创建相同职责的机制。
- 只在用户要求实现或明确授权写入时修改文件；其余情况给出可执行的变更规格。
- 验证范围与改动风险匹配。报告已运行检查、未运行检查及其原因，不把静态阅读描述成运行时验证。

## 证据约定

每个重要结论都区分三类信息：

- 已验证事实：可定位到源文件、配置、资产或可复现的运行结果。
- 候选线索：搜索、检索或相似实现返回的可能关联项。
- 未确认项：缺少权限、环境、数据或运行条件而不能确认的内容。

候选线索不能单独证明代码所有权、生命周期、网络权威、持久化、清理或线上调用关系。

## 交付约定

涉及改动时，交付内容至少包括：目标、涉及文件、核心决策、风险、验证结果和未覆盖项。发现需求与现有结构冲突时，说明冲突及可行替代方案，不通过隐蔽扩展绕过约束。
