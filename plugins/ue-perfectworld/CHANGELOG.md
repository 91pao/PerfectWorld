# UE PerfectWorld 更新日志

本日志只记录 Git 中可核实的 UE PerfectWorld 版本。`0.1.1` 没有对应的独立发布提交或插件清单版本，故不补写；早于 `0.1.0` 的仓库记录属于 marketplace 历史，见根目录 [CHANGELOG.md](../../CHANGELOG.md)。

## 0.3.0 - 2026-08-06

- 新增与 `ue-project-rag` 的可选联动。大型项目可先检索符号、配置、文档和资产元数据，再缩小后续调查范围。
- RAG 只承担候选发现：检索评分、摘要和资产元数据不能证明所有权、生命周期、网络权威、持久化、清理或 Blueprint 运行时行为。
- 规划、排查、直接实现、审查、Blueprint 集成和只读变更规格工作流都会在 RAG 工具可用时加载联动规则；工具不可用时继续使用直接项目搜索。
- 将未授权写入时的交付收敛为变更规格，明确已验证证据、变更面、依赖、风险和验证条件。
- 更新插件描述与关键词，使其反映项目证据优先和本地检索协作的定位。

## 0.2.0 - 2026-07-27

- 新增现有能力准入门禁：在允许新机制前检查完整类型继承、继承编辑器属性、Blueprint Designer 配置、项目数据、路由和活跃生产调用者。
- 要求将每项职责分类为 `reuse`、`configure`、`extend` 或 `create`；只有当前项目证据排除兼容的复用与配置路径后，才允许扩展或创建。
- UI 交互和表现优先采用现有控件配置、继承组件或基类属性、表或路由配置和既有辅助函数，其次才是局部代码和共享框架修改。
- 新 DataAsset、红点身份、存档结构、RPC、代理状态、委托、管理器、同步路径和生命周期覆写若只服务于展示或导航，将触发阻断式复杂度检查。
- 后续证据发现项目已有能力时，必须删除为先前错误能力缺口引入的补偿机制，不能保留并行实现作为兼容路径。
- 准入门禁继续集中在项目一致性和最终自审规则中，所有 UE 工作流自动继承，没有增加新的技能或规则文件。

## 0.1.9 - 2026-07-25

- 新增完成声明门禁，将责任证据矩阵和变更面清单转换为已验证、已否证、不可验证或不适用的明确状态。
- 存在必要职责或执行阶段被否证、不可验证时，禁止声称实现完整、最终、就绪、最佳或审查没有问题。
- 最终结论必须说明实际达到的最高验证等级，禁止把源码检查描述为编译、运行、网络权威、持久化、跨会话或跨平台验证。
- 增加针对缺失、格式错误、陈旧、重复、未激活、重复输入、延迟或乱序回调、重新加载、重连和清理等适用失败场景的集中检查。
- 门禁继续复用现有证据和最终自审规则，所有 UE 工作流自动继承，不增加新的规则文件或具体功能策略。

## 0.1.8 - 2026-07-24

- 明确拆分状态生产与持久化所有者、确认或消费所有者，以及只负责展示的消费者。
- 多个界面或系统展示同一状态时，必须复用同一权威身份，禁止无依据地增加代理状态、转发事件、镜像存档或同步代码。
- 将 `NEW`、角标、数量和不同 Brush 等视觉差异默认视为表现层，只有经过验证的业务规则才能把它们定义为独立状态。
- 新增入口、配置、路由、目标解析、创建、表现、确认、持久化和清理的执行阶段映射，避免把不同阶段误判为重复系统。
- 新增阻断式变更面清单，将文件、资产、表行、Tag、注册点和 Blueprint 绑定标记为创建、替换、配置或仅复用；未声明的共享框架改动会重新触发能力匹配门禁。
- 最终自审扩展到 C++、工厂注册、DataAsset、DataTable、GameplayTag、Blueprint 绑定、UI 扩展与平台覆写、外部数据、持久化和清理的完整契约。
- 复制编辑器表行或资产时，要求保留已验证的隐藏字段，同时替换仍指向源功能的平台专用引用。

## 0.1.7 - 2026-07-24

- 在实现、补偿或扩大范围前新增阻断式需求与能力匹配门禁。
- 要求冻结用户最新需求和硬边界，删除只属于已废弃需求的行为、状态、兼容分支与扩展机制。
- 要求每项行为优先映射到已经拥有该职责的最高层项目能力，不能先假设缺少能力再自行补建局部系统。
- 当需求与允许范围冲突时，必须说明准确冲突、不可避免的严格实现成本和最接近的项目原生替代方案，交由用户决定，不能虚构局部补偿。
- 新增文件、共享集成点、状态所有者、持久化路径、RPC、缓存、委托、定时器、管理器或配置源时，必须重新执行匹配门禁。
- 最终自审新增过时行为、隐藏范围扩张和需求变化过程中累积的无用机制检查，并将门禁接入规划、排查、变更规格、直接实现、审查和 Blueprint 工作流。

## 0.1.6 - 2026-07-23

- 新增职责证据矩阵，禁止用一个相似功能同时证明 UI 组合、导航、状态、生命周期、防护和诊断等不同职责的实现方式。
- 要求项目专用的对象获取、空值防护、可选控件处理、回调校验和日志行为分别匹配同职责、同生命周期的活跃代码证据。
- 禁止统一采用“每个返回都记录日志”或“所有失败都保持静默”的策略，必须先区分失败类型并遵循项目已有处理路径。
- 新增遍历、直接管理器调用、绕过包装层、查找路径或日志策略时，必须重新打开项目调查，不能沿用无关先例。
- 最终自审新增重复边界日志、虚构 HUD/玩家访问方式、可选控件处理不一致，以及单纯为减少日志或行数而改变设计等阻断检查。
- 将职责证据门禁接入规划、排查、Blueprint 协作、变更规格、直接实现和审查工作流，没有增加重复规则文件。

## 0.1.5 - 2026-07-23

- 为非简单跨系统 UE 设计新增强制证据门禁，完整代码、编辑器配置、直接修改或框架扩展之前都必须通过。
- 要求分别证明权威数据或配置源、运行时所有者与生命周期、触发路径、读取或确认路径、持久化以及清理或过期路径。
- 禁止用相邻职责互相代替证据：父子聚合不能证明消息创建，UI 展示不能证明服务端持久化，触发路径不能证明清理路径。
- 要求将未解决问题拆分为可验证子问题，穷尽当前项目搜索和端到端追踪后，只向用户询问项目外部资料或真实业务决策。
- 缺少必要证据时必须明确报告缺口，不得虚构条件、管理器、DataAsset、字段、委托或生命周期钩子。
- 将证据门禁接入规划、排查、Blueprint 协作、变更规格、直接实现、审查、最终自审和连续失败恢复流程。

## 0.1.4 - 2026-07-23

- 将证据、所有权、可维护性和失败恢复要求合并进项目一致性、变更规格和最终自审的权威规则，删除三份重复 reference。
- 新增 `ue-complete-implementation.md`，统一管理只读变更规格、跨系统设计确认和验证要求。
- 将工作流规则改为“核心加按需”模型：网络、事务、UI 参数、编码、注释日志和 bug 修复规则只在相关任务中加载。
- 将路由器收敛为纯工作流选择，不再预加载会由已选技能再次读取的 reference。
- 将未授权写入的输出规范调整为项目证据、变更面和验证边界，减少与直接实现工作流的重叠。

## 0.1.3 - 2026-07-22

- 将插件清单版本更新为 `0.1.3`，引入证据与可维护性门禁。
- 对项目一致性、最终自审、调查、规划、实现、审查和 Blueprint 工作流补充所有权、生命周期与可维护性要求。
- 仅在用户明确授权时写入项目；未授权时保留完整的变更说明与验证边界。

## 0.1.2 - 2026-07-22

- 发布 `0.1.2`，补充客户端与服务端边界、异步回调和失败恢复检查。
- 扩展 bug 修复与最终自审规则，要求区分已证实的根因、未验证假设和未覆盖路径。

## 0.1.0 - 2026-07-17

- 首次发布 UE PerfectWorld，提供规划、排查、实现、审查、Blueprint 协作和工作流路由能力。
- 建立项目一致性、编辑安全、网络边界、UI 参数契约、注释与日志、变更漂移和最终自审等基础规则。
