# UE Paste Code Gate

凡生成将要贴入 UE 项目的代码必须执行的本门禁，交付形态两种皆适用：直接编辑项目文件、以可粘贴的 Markdown 规格交付。贴码规格没有编译器兜底——每一个符号级错误都会转嫁给贴码人，且只在对方编译期才暴露。因此验证发生在生成时，而不是编译时。

## 适用范围

- 覆盖整函数、局部改动、声明、测试代码、蓝图暴露 API 新增、include 语句。
- 直接编辑项目文件不豁免：同一套检查照跑，编译器只改变错误暴露时机，不改变错误可预防性。

## 查证清单（写码前与写码中）

1. **符号查证。** 写下每个新增符号（函数、字段、委托、常量、测试访问器）之前，先在全模块 grep 同名，确认不存在既有符号——排查范围包含测试访问器与编辑器专属辅助结构。引用每个既有符号时， grep 它的**声明处**并确认三件事：可见性（public/private/friend）、性质（方法、委托成员、数据成员）、完整签名。禁止凭命名惯例推断——`Started` 结尾的名字可能是返回 void 的方法，不是可订阅的委托。
2. **API 参数语义从实现读取。** 调用既有 API 时，读到其实现的完整分支逻辑后再决定参数值。函数签名只说参数类型，不说语义约束——"传无效 GUID 走创建分支、传有效但未注册的走复用查找"这类信息只存在于实现里。从参数名或类型推断语义等于把运行时失败转嫁给贴码人。
3. **include 先例。** 每个新增 include，在同一模块内找一个**现成的同目标包含**照抄其写法（裸文件名还是带路径前缀）。禁止按目录结构拼路径；同一目录下 `AIDelivery/Public/` 的头文件可能裸名包含，`AIDelivery/Adapters/` 却带路径前缀。
4. **完整读取。** 整函数替换前必须读到该函数的结尾大括号——`grep -A` 截断输出不是函数全貌，尾部清理段与状态标志赋值活在可见窗口之外。每个定位块（找到→改成）必须当轮现场生成；禁止把早前轮次记住的文件内容用于另一个文件的头文件与实现文件会漂移。

## 自检清单（交付前）

4. **依赖闭包。** 全部改动写完后，按"谁引用谁的定义"排出贴码顺序，逐批验证可独立编译。提交批次与贴码顺序不同时，单独列出各批内容并验证批内自洽。
5. **文件级定位。** 规格的每个小节标题携带目标文件全名（含 `.h`/`.cpp` 后缀）；头文件与实现文件的插入点分开指定，各自带定位锚。
6. **诚实缺口。** 无法静态验证的项（运行时时序、自动化世界的时间推进、日志精确文本）显式标注为现场校准项；禁止占位断言与编造内容。
7. **文档交付的升级标准。** 交付形态为可粘贴文档时，查证标准提高一级：每个符号从声明处核验（不是"我记得它存在"）、每个 API 参数从实现处核验、每个锚点当轮重新生成（不是复用记忆）。理由：直接编辑有编译器做免费第一轮，文档交付没有——验证手段少了，人工验证必须补上。质量门禁跟着代码走，不跟着交付形态走。

## 本门禁预防的失败类别

- 同名符号冲突：访问器或辅助函数在文件或其测试访问器里已存在。
- 访问违规：未走 friend 访问器引用私有接缝；把方法当委托调用。
- include 路径错误：拼出来的路径而非照抄先例。
- 尾部逻辑丢失：凭截断读取替换整函数，清理段与状态标志被丢。
- 陈旧锚点：定位块来自另一文件早前轮次的读取，局部变量名对不上。
- 批次断链：某贴码批次引用了后一批次才定义的符号。
